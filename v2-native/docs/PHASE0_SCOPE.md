# 阶段 0 范围

版本：1.0｜日期：2026-09-05｜性质：规则冻结，不是实现证明

本文只定义阶段 0 的工作边界、允许产物和出关条件。已冻结产品决策见 `DECISIONS.md`；数据与 AI 边界见 `TRUST_ZONES.md`；财务口径与公式见 `FINANCE_RULES.md`。权威目标方案仍是 `PRODUCT_BASELINE.md`。三者冲突时，以基线原文为准，并在决策日志登记，不得在本文改写规则。

阶段 0 **没有**可运行的 V2 账本、界面或设备协议。本文出现的模块名、命令名和表名是目标设计，不表示仓库里已经存在对应代码。

## 1. 本阶段要完成什么

阶段 0 的目的是：在写 Kotlin、Room 或 Compose 之前，把范围、信任边界和财务口径冻到可以编码。规划工期 1–2 周，是估算不是交付保证。

产品要服务的四件事（目标，非现状）：

1. 知道今天要做什么。
2. 低成本记录真实发生的事。
3. 知道钱去了哪里，以及还有哪些往来未结清。
4. 通过手机或终端获得一致的提醒与反馈。

阶段 0 只冻结这四件事在 V2 里的规则与边界，不交付能完成它们的应用。

## 2. 工作区与旧运行时

| 路径 | 阶段 0 角色 | 允许动作 |
|---|---|---|
| `android/`（包名 `app.selfagent`） | 正在使用的正式旧运行时 | **禁止改动**。继续独立维护与回退；本阶段不修功能、不改签名、不接 V2 |
| `v2-native/` | V2 阶段 0 工作区 | 只允许产品、架构、规则、迁移盘点、页面线框和任务拆解 |
| 旧 WebView / React 业务页 | 迁移来源与历史查看 | 不进入 V2 运行路径；不在本阶段删除旧数据或旧应用 |

硬约束：

- 阶段 0 不创建 Gradle 模块、Room schema、Compose 空页面、AndroidManifest 或可写业务实现。
- 阶段 0 不接入旧版运行路径，不把 V2 文档里的命令接到现有 JS/Kotlin 桥。
- 内测 applicationId 拟为 `app.selfagent.v2`，与旧版并行安装；本阶段不生成该包的工程骨架。
- 旧 Keystore 中的密钥通常不能直接搬到另一个 applicationId。本阶段只记录这条事实，不实施迁移。

- 编写或修订 `v2-native/docs/` 下的范围、决策、信任区、财务规则、线框、旧资产盘点、待办拆解。

- 用静态线框或纸面流程表达四栏导航与核心录入路径；线框不是可编译界面。
- 列出旧数据样本需求与签名盘点项；不把真实备份、证书口令或密钥写入仓库。

### 禁止

- 在 `v2-native/` 或仓库其他位置添加可写业务代码、构建脚本、空模块或演示数据库。
- 修改 `android/`、现有 Web 业务核心、CI 发版工作流、签名材料。
- 声称某条财务、AI 或设备能力“已经在 V2 实现”。
- 把演示金额、真实账本、密码、API Key、完整卡号写入文档或仓库。
- 为了目录整齐拆出几十个空包，或顺手追加 iOS / 可写网页核心。

不确定是否允许时：**不做**。阶段 0 失败关闭。

## 5. 十个关键场景（出关锁）

阶段 0 出关条件之一：下列十个场景 **没有未决口径冲突**。场景的分录、公式和拒绝条件以 `FINANCE_RULES.md` 为准；产品入口与失败关闭以 `TRUST_ZONES.md` 为准。

| 编号 | 场景 | 必须锁死的问题 |
|---|---|---|
| S1 | 工资入账 | 算收入、增加净资产；不与报销收回混淆 |
| S2 | 资金账户消费 | 算个人消费、减少资金与净资产 |
| S3 | 同币种转账 | 不算收入或消费；组合层现金流抵消 |
| S4 | 信用卡消费 | 算消费、增加欠款；不是现金流出 |
| S5 | 信用卡还款 | 不重复算消费；还款才是资金流出；溢缴款进资产侧 |
| S6 | 垫付拆分 | 个人承担 + 垫付 = 实付；垫付部分不算消费 |
| S7 | 部分报销收回 | 资金增加、应收减少；不算工资；禁止超额塞回原事项 |
| S8 | 借入与还本息 | 本金往来与利息费用分开；本金不算收入或消费 |
| S9 | 真实退款 vs 冲销 vs 更正 | 三件事；原凭证不可变；退款归属退款日 |
| S10 | 余额校正与缺汇率 | 校正必填理由且不伪装收支；缺汇率绝不 1:1 |

配套日常闭环（用于线框，不另开口径）：早上查看今天、买午餐记账或通知草稿、晚上按真实任务复盘、断网本机提交成功且外部能力显示不可用。这些闭环若与上表冲突，以上表和 `FINANCE_RULES.md` 为准。

## 6. 出关条件

同时满足以下全部条件，才允许进入 F-01（Money 与币种解析）。任一未满足则失败关闭，不得“先写代码再补规则”。

1. 用户确认 `PRODUCT_BASELINE.md` 仍是目标方案；阶段 0 文档不与其沉默漂移。
2. 本文的允许/禁止清单被遵守：`android/` 未被本阶段改动；`v2-native/` 无 Gradle/Compose/Room 实现。
3. `DECISIONS.md` 把已冻结项和未决项分开；所有 **阻断 F-01** 的未决项要么关闭，要么明确降级为后续阶段。
4. `TRUST_ZONES.md` 写明财务、健康、日程、密钥、设备、备份、日志、AI 的默认拒绝规则。
5. `FINANCE_RULES.md` 中 S1–S10 无互相矛盾的公式或符号约定。
6. 用户确认页面线框（四栏：今天、账本、生活、助手）与 S1–S10 的录入/查询路径。
7. 旧数据样本需求与签名盘点已记录，且仓库中无密钥、口令、证书文件。
8. 待办清单中 F-01 的依赖仅为已冻结规则，不依赖未写的实现。

未决但 **不阻断** F-01 的项（板型、具体 KDF 库、厂商覆盖表等）必须留在 `DECISIONS.md`，不能假装已定。

## 8. 完成定义（阶段 0）

阶段 0 完成，只意味着：范围清楚、口径无冲突、信任区失败关闭、旧运行时未被触碰、可以开始 F-01。

它不意味着：用户已经能记账、AI 已经能协助、旧账已经迁完，或任何性能指标已经达到规划值。
