# 财务规则基线

版本：1.0｜日期：2026-09-05｜性质：不变量与口径，不是已上线账本

本文是 V2 财务域的唯一口径。页面、助手、设备草稿、报表必须引用这里的公式，不得各写一套。阶段范围见 `PHASE0_SCOPE.md`；冻结/未决见 `DECISIONS.md`；谁有权看见财务数据见 `TRUST_ZONES.md`。

旧运行时 `android/` 与其中的 JS 账本 **保持不动**。旧规则与测试只作反例和迁移素材，不逐行翻译，也不构成本文已经落地的证据。V2 尚无 Room、命令服务或可写界面。

内部符号：借方为正，贷方为负。下文金额未标明币种时，例子使用 CNY 最小货币单位的十进制读法（100 表示 100.00 CNY），便于评审；实现必须用整数最小单位，见 §2。

## 1. 核心模型

- 用户账户（银行卡、现金、信用卡等）与账务科目分离。收入、费用、期初权益、换汇清算是系统科目，不得出现在“我的账户”列表里冒充银行卡。
- 已入账事实是凭证 `JournalEntry` + 分录 `Posting`。往来是 `Claim`；到账分配是 `SettlementAllocation`。
- 候选草稿不进已入账表。
- 账户余额只来自流水：期初凭证 + 全部已入账 posting（含冲销）。查询缓存可删，不能当第二真相。
- 负债展示从账务符号转换。信用卡借方余额是溢缴款，计入资产侧，禁止把负债小于零截成零却仍显示“欠款”。

## 2. 金额、币种、失败关闭

```
Money = 有符号 64 位整数（最小货币单位）
币种 ∈ {CNY, USD, HKD, EUR, JPY}   # MVP 已支持列表；列表外拒绝
```

- 字符串直接解析为 Money。禁止 `Double` 中转。
- 加减必须检查溢出；溢出拒绝整笔命令。
- 非法、空缺、非数、超范围：显式拒绝。禁止改写成 0，禁止改成绝对值后入账。
- JPY 小数位必须为 0；出现小数即拒绝。
- 账户币种：无流水前可设；有流水后不可改。已有流水改账户类型必须走受控迁移，不得改历史含义。
- 数量、汇率、报价使用限定精度的十进制；只在入账或展示边界舍入。具体精度与舍入模式见决策日志 Q-01；模式未定时 **拒绝** 需要舍入的入账，禁止静默截断。
- 多币种分别汇总。折算必须保存基准币、汇率来源、有效时间、估值时间、缺失范围。
- 缺汇率：显示“已知部分估值 + 未折算明细”。**禁止默认 1:1，禁止不同币种直接相加。**

## 3. 必须成立的等式

对任意已提交事务，下列式子必须可重算且一致。任一步失败则整笔回滚。

**凭证平衡**（每个凭证、每个币种各自成立）：

```
Σ posting.signedMinor(journalId, currency) = 0
```

**账户余额**：

```
balance(userAccount, currency)
  = Σ posting.signedMinor
    其中 posting 已入账
    且 posting.ledgerAccount 映射到该 userAccount
    且 posting.currency = currency
```

冲销分录与原分录都进入上式。禁止靠隐藏原记录把总额“调对”。

**拆分支付**：

```
个人承担 + 垫付应收 = 本次实际支付
个人承担 ≥ 0，垫付应收 ≥ 0
任一为负或两者之和 ≠ 实付 → 拒绝
```

**未结往来**：

```
未结金额 = 确认应收 − Σ 有效 SettlementAllocation − 明确核销
未结金额 ≥ 0
本次分配 > 未结金额 → 拒绝（超额不得塞回原事项）
```

一个到账可分配给多个事项。超额部分必须另记为其他收入、预收或新往来，不得修改原事项金额使等式碰巧成立。

第一阶段：结算双方币种必须相同，否则拒绝。

## 4. 报表口径

名称、说明、公式固定。垫付不得在不同页面随机算作消费。

**个人消费**（期间 P，币种 C，账本时区）：

```
个人消费(P, C)
  = Σ 费用科目 posting.signedMinor    # 业务日期 ∈ P，币种 C，已入账
    对真实退款：计入退款发生期，方向为冲减原费用类别
不含：转账、信用卡还款本金、往来本金收回/借入/还本、
      全额垫付的应收部分、余额校正、投资成本结转、结算分配本身
```

费用科目借方为正，故消费增加时个人消费为正数。退款在退款期减少该值。

**资金现金流**（用户勾选的资金账户集合 A，期间 P，币种 C）：

```
流入  = Σ 对 A 的正 posting（P, C）
流出  = Σ 对 A 的负 posting（P, C） 的绝对值
净额  = 流入 − 流出
```

- 组合层：A 内部互转抵消。
- 单账户视图：仍显示该账户真实流入流出。
- 信用卡消费 **不是** 资金账户现金流；信用卡还款才是资金流出。
- 全额垫付：现金流出 = 实付，个人消费 = 0。

**净资产**（估值时刻 T）：

```
净资产(T)
  = Σ 资产类账户余额（含溢缴款）
  + Σ 应收未结
  − Σ 应付未结
  − Σ 信用卡欠款（贷方余额的负债含义）
  + 已启用投资时的持仓估值（市价更新不产生消费流水）
```

多币种不得混加。缺汇率时：已知部分估值 + 未折算明细，并标记估值不完整。市价不是成交价；未实现与已实现分栏。核心版不开投资写入。

首页、账户详情、报表、AI 引用数字时，必须携带同一组查询参数（币种、日期窗口、时区、口径版本）。参数不同则禁止宣称“数字一致”。

## 5. 十个关键场景

符号均为内部借贷符号。每个场景给出：用户动作、分录、报表、必须拒绝的变体。金额为例子，不是演示数据种子。

### S1 工资入账

用户：工资到账 100，进入资金账户 W（CNY）。

```
W 资金          +100
收入科目        −100
个人消费：不变
收入报告：+100
净资产：+100
现金流：W 流入 100
```

拒绝：W 不存在/已归档；币种与 W 不同；金额 ≤ 0 或溢出；把报销收回记成工资。

### S2 资金账户消费

用户：从 W 支付午餐 30。

```
费用科目        +30
W 资金          −30
个人消费：+30
净资产：−30
现金流：W 流出 30
```

拒绝：金额空缺；无账户；未确认草稿当已入账。两次真实的 30 元午餐保持两笔，不得因金额相同自动合并。

### S3 同币种转账

用户：W → 账户 B，100，同为 CNY。

```
B 资金          +100
W 资金          −100
个人消费：不变
收入：不变
净资产（同币种）：不变
现金流：单账户有流入流出；勾选 {W,B} 的组合层净额 0
```

拒绝：同账户转账；币种不同（本阶段）；缺对方账户。

### S4 信用卡消费

用户：信用卡 CC 消费 30。

```
费用科目        +30
CC 负债         −30
个人消费：+30
欠款增加 30
现金流（资金账户）：0
净资产：−30
```

拒绝：把该 30 再记入资金账户流出；负债展示截断为 0。

### S5 信用卡还款与溢缴款

用户：从 W 还 CC 30。

```
CC 负债         +30
W 资金          −30
个人消费：不变（不重复计消费）
现金流：W 流出 30
欠款减少 30
```

若还款后 CC 出现借方余额（溢缴款）：该余额进入资产侧，文案为溢缴款，不是“欠款 −x”。

拒绝：还款命令改写原消费凭证；无资金账户。

### S6 垫付拆分

用户：实付 300，其中 200 可报销、100 个人承担，从 W 付出。

```
费用科目        +100
应收 Claim      +200
W 资金          −300
校验：100 + 200 = 300
个人消费：+100
现金流：W 流出 300
净资产：−100   # 应收 +200 与资金 −300 净 −100
未结应收：200
```

全额垫付 200（个人承担 0）：

```
应收            +200
W 资金          −200
个人消费：0
现金流：流出 200
净资产：不变
```

拒绝：两数之和 ≠ 实付；把 300 整笔记成消费；报销当成一种资金账户。

### S7 部分报销收回

承接 S6 全额垫付 200 后，收回 120 进入 W。

```
W 资金          +120
应收            −120
个人消费：不变
收入报告：不变（不算工资）
未结应收：80
净资产：不变
现金流：W 流入 120
```

分配记录必须指向原 Claim。允许部分收回。

拒绝：分配 201（超额）；用普通收入或任意“关联 ID”冲减应收；已有结算的垫付被直接删除且默默撤销用户已收到的 120；跨币种结算（本阶段）。

### S8 借入与还本息

借入 100 进入 W：

```
W 资金          +100
应付            −100
收入：不变
净资产：不变
```

还本金 100、利息 5，从 W 付出 105：

```
应付            +100
利息费用        +5
W 资金          −105
个人消费/费用：仅 5
应付未结：0
现金流：W 流出 105
净资产：−5
```

拒绝：把 100 本金算收入或消费；利息并入本金使往来消失。

### S9 真实退款 vs 冲销 vs 更正

三件事，禁止互相替代。

| 用户意图 | 系统 | 日期 |
|---|---|---|
| 记错了，需要纠正 | 新的反向凭证；记录纠正时间、被纠正 ID、原因 | 可归属原业务日期展示“已更正”，同时保留录入时间审计视图 |
| 修改已入账字段 | 原凭证不可变；同一数据库事务内：反向凭证 + 新凭证（新 ID，supersedesId 指向旧 ID） | 任一步失败全回滚 |
| 商家真实退回 20 | 新增退款交易，关联原消费；资金 +20，原费用类别 −20 | 归属实际退款日期；退款发生期冲减消费 |

```
退款 20：
W 资金          +20
原费用类别      −20
个人消费（退款日所在期）：−20
不是工资或普通收入
```

拒绝：编辑冲销凭证；对已冲销原凭证再次冲销（再次请求返回既有结果）；无关联原件的退款/冲销；用退款抹掉原消费事件使其 ID 消失。

发生时间、业务日期、录入时间、纠正时间分存。默认报表按业务日期。

### S10 余额校正与缺汇率

余额校正：账户与校正权益科目相抵；必填理由并留痕；不进入收入/消费。

```
例：W 资金      +7
    校正权益    −7
个人消费：不变
收入：不变
```

拒绝：直接改 balance 字段；无理由；用校正修复本应存在的缺失交易而不展示差异。

缺汇率估值：持有 USD 账户且无可用汇率时，净资产页必须同时给出已知 CNY 估值与未折算 USD 明细。禁止 1 USD = 1 CNY。不同币种转账本阶段拒绝。JPY 带小数拒绝。

## 6. 核心必须拒绝的输入

下列任一出现，命令失败关闭，不得入账：

1. 账户不存在或已归档
2. 币种与账户不匹配
3. 同账户无意义转账
4. 金额非法、空缺、零（对必须正数的命令）、溢出
5. 凭证不平衡或某币种 posting 之和非零
6. 缺必要对方账户
7. 未知命令、非法状态转换
8. 重复 commandId 但 payload 不同（冲突）；相同则返回旧回执
9. 旧版本确认（expectedRevision 不匹配）
10. 无关联原件的退款或冲销
11. 超额结算
12. 缺汇率的换汇
13. 未确认草稿
14. 直接改账户余额字段

人工重复记账只用相似检测提示，不自动合并。

## 7. 冲销、结算依赖、中断

- 已有关联结算的垫付不可直接删除。界面必须列出依赖；允许保留历史并新增纠正，或在同一事务内撤销必要关联。不得默默撤销用户实际收到的款项。
- 每个写入步骤都按“全部成功或全部未提交”设计。中断后不允许：半笔交易、无回执已扣款、重复扣款。
- 周期账单只生成建议/草稿。确认前不增加消费、不减少余额、不标记已扣款。规则 + 账期 + 规则实例是唯一来源键。

## 8. 投资（核心版关闭写入）

目标规则预告，避免以后把估值写进消费：买入减少现金并增加成本与份额；卖出结转成本、增加现金、单列已实现损益；股息是投资收入；股息再投资是第二笔关联交易。市价更新只改估值。历史产品缺成本或份额时不得反推精确收益。核心版用户继续在旧版查看，或待阶段 4 明确迁入。

## 9. 与十关发布门槛的关系

基线 §12.1 的十条财务硬门槛是 **阶段 1 及以后的实现验收**，不是阶段 0 的代码结果。阶段 0 只保证：S1–S10 与 §3–§6 的公式无未决口径冲突。未写出 F-01，未跑随机交易序列，未做中断注入。不得把本文当作那些门槛已经通过。
