本文只登记决策状态。阶段边界见 `PHASE0_SCOPE.md`；信任区细则见 `TRUST_ZONES.md`；财务公式与十场景见 `FINANCE_RULES.md`。来源：`PRODUCT_BASELINE.md`（2026-09-05，v1.0）与 `v2-native/README.md`。

本文件不含密钥、口令、证书指纹以外的签名机密。旧运行时 `android/` 仍独立存在，决策生效对象是尚未开工的 V2，不是对旧应用的既成事实。

## 1. 已冻结

| ID | 决策 | 备注 |
|---|---|---|

### 1.3 架构契约

| ID | 决策 |
|---|---|
| D-15 | 写入只走有定义的命令；查询只走有定义的查询；UI、AI、设备不得绕开 |
| D-16 | 命令外壳含 commandId、type、schemaVersion、source、requestedAt、expectedRevision、payload、payloadHash；身份由应用或配对会话确定，不信任输入自报角色 |
| D-17 | 同一 commandId + 同一 payload 返回已有结果；同一 ID 不同 payload 返回冲突 |
| D-18 | 候选草稿单独存储，不得先写入已入账表再靠页面过滤 |
| D-19 | 余额唯一来源是流水；缓存可删可重建，不能当第二套真相 |
| D-20 | 禁止直接 UPDATE 账户 balance 字段；余额调整必须是显式命令 |
| D-21 | 领域层不得依赖 UI、Room 实现或网络；金额规则只在一处定义 |
| D-22 | 界面状态为 loading / empty / ready / saving / failed；保存成功只来自事务结果 |
| D-23 | 财务规则和旧测试作反例与素材，不把现有函数逐行翻译成 Kotlin |
| D-24 | 支付、旅行、Gadgetbridge 等 Kotlin 解析器可在复核格式、权限、幂等、失败行为后封装为适配器复用 |
| D-25 | 旧测试保留为历史基线；新系统按业务不变量重建测试 |

### 1.4 财务口径指针

财务符号、公式、S1–S10 的完整定义只在 `FINANCE_RULES.md`。这里只冻结方向，避免两处各写一套数：

| ID | 决策 |
|---|---|
| D-26 | 内部复式记账；用户语言仍是收入、支出、转账、退款、垫付、收回、借入、还款 |
| D-27 | 借方为正、贷方为负；每张已入账凭证在每个币种内 posting 之和必须为零 |
| D-28 | Money 为受控范围有符号 64 位最小货币单位整数；禁止经 Double 再解析 |
| D-29 | MVP 币种：CNY、USD、HKD、EUR、JPY；JPY 拒绝小数 |
| D-30 | 缺汇率时显示已知估值 + 未折算明细；禁止默认 1:1 |
| D-31 | 第一阶段只开放同币种结算 |
| D-32 | 冲销、编辑已入账、真实退款是三件事；原凭证不可变 |
| D-33 | 核心记账账户币种在有流水后不可改 |

## 3. 未决

### 3.1 阻断 F-01 的未决

当前 **无**。S1–S10 口径以 `FINANCE_RULES.md` 为准；若评审发现互相矛盾，本表必须重新出现阻断项，且 F-01 不得开工。

Money 的溢出上限、已支持币种列表的机器可读配置、以及舍入发生的代码边界，属于 F-01 实现任务，但 **策略** 已在财务规则中冻结为：显式拒绝非法值，禁止变成 0 或取绝对值。

### 3.2 不阻断 F-01，必须在注明阶段关闭
